Service Level Agreement (SLA)

Elevator & Lift Services - configuration, execution and escalation workflow

Purpose

An SLA defines the time commitments for handling a service request. It measures response, assignment, dispatch, arrival, work start, resolution and escalation.

Provider SLA tiers

The Provider Override screen offers controlled tiers. The selected tier should map to a canonical platform SLA policy before runtime enforcement.

TierUI meaningOperational interpretation
Premium 24HFaster response profilePriority service commitment. The 24-hour label should normally describe initial response unless resolution is explicitly defined.
Standard 48HNormal response profileRoutine breakdowns, inspections and non-critical maintenance requests.
Basic 72HLower urgency profilePlanned or lower-priority work where a longer response window is acceptable.
Safety rule

Entrapment, fire, uncontrolled movement and other safety-critical incidents require a separate emergency SLA and escalation policy. They must not wait for a normal Premium 24H commitment.

Elevator & Lift operational examples

Different service scenarios need different urgency and response behavior.

ScenarioPolicy selectionExpected flow
AMC inspectionStandard or BasicReminder -> assignment -> visit -> checklist -> report -> close.
Lift breakdownPremium or service-specificRequest -> priority -> assignment -> dispatch -> arrival -> diagnosis -> repair or parts -> resolution.
Entrapment or safety eventEmergency policyImmediate alert -> emergency assignment -> escalation -> acknowledgement -> site response -> safety confirmation -> evidence.
Installation project issueProject-specificIssue -> project team assignment -> target milestone -> corrective action -> acceptance -> close.

Milestones measured by the platform

MilestoneWhat it measures
ResponseProvider acknowledged or contacted the customer.
AssignmentAuthorized technician or team accepted the work.
Dispatch and arrivalTechnician was sent and reached the site.
Work startTechnician began diagnosis or repair.
ResolutionService outcome was completed and evidence recorded.
Operational benefit

SLA makes service commitments visible to customers, technicians, supervisors and the platform team. It provides objective evidence for provider performance, escalation and contract review.

Platform implementation mapping

The Provider Override screen stores the selected tier as configuration. The runtime engine should resolve that value to canonical SLA records used for execution and escalation.

Configuration layerRuntime layerRequired behavior
Provider override tierSLA policyMap tier codes to versioned policies with exact target minutes.
Priority and emergency rulesSLA executionSelect the policy at request time and snapshot its version for auditability.
Business hours and pause rulesEscalation recordsCalculate timing consistently and create escalation records when risk or breach thresholds are reached.
Recommendation

Keep SLA tier selection controlled by Platform Administration. Add a master mapping table so every tier points to an approved SLA policy, business-hours rule, pause/resume rule and escalation policy. Provider users should not enter arbitrary SLA text.

All timestamps and target calculations for this project should use Asia/Kolkata.
